title: "OasisKV reproduction"
description: "Lookahead KV prefetch for MHA/GQA, MLA, native DSA, and DeepSeek-V4 on the oasiskv branch."
---

This branch implements the lookahead execution contract from [OasisKV v1](https://arxiv.org/pdf/2608.08097v1): run a real token and one draft token through the target, use the draft query to prepare the next working set, and commit only the real token. You need a compatible EAGLE-3 or DSPARK draft checkpoint trained for your target's feature interface; an arbitrary smaller language model is not a substitute.

The generic backend and DeepSeek-V4 specialization include full CUDA graph decode paths with captured selection and transfer streams. CPU reference, Triton interpreter, and integration tests cover attention, ownership, configuration, and memory accounting. Capture/replay, full model generation, quality, and performance still require validation on NVIDIA GPUs. This branch does not implement the paper's remote partial fetch service or claim its reported speedups.

## Choose a path

| Target attention | Selection for next step | Target KV storage | Entry point |
| --- | --- | --- | --- |
| MHA / GQA | Quest min/max bounds per KV head, maximum across that head's query group | Shared GPU pages while dense; pinned CPU history and bounded GPU pages after the sparse threshold | `--attention-backend oasiskv` |
| Ordinary MLA | Quest over the absorbed latent-plus-RoPE keys and queries | One latent KV head with separate key and value dimensions | `--attention-backend oasiskv` |
| Native DSA, including DeepSeek-V3.2 / GLM DSA | The model's real draft-row indexer Top-K, before physical-page translation | CPU latent KV; bounded GPU KV slots; native indexer key cache stays on GPU | `--attention-backend oasiskv` |
| DeepSeek-V4 | C4 draft-row indexer Top-K | Existing HiSparse C4 host/device pools and transactional scratch | `--enable-hisparse`, `prefetcher="oasiskv"` |

For the generic path, both rows attend to the history selected by the real query. The draft row can also see its own provisional KV; the real row cannot. Only real KV enters committed history. Prediction, real-query miss refill, and attention run on the foreground CUDA stream. Read-only LRU planning runs on a selection stream; UVA transfer runs on another stream and waits for both selection and the current layer's attention reads. KV uses shared physical pages without staging or double buffering. Each CUDA decode CTA loads a historical K/V tile once for the real/draft pair and maintains separate softmax accumulators. Each layer waits for its own previous transfer before reuse. Releasing or reusing a request waits for outstanding selection and copies before freeing pinned memory.

Dense requests use the existing paged extend attention kernel over the shared page table, without gathering KV into a contiguous buffer. Long requests that have crossed the sparse threshold use chunked causal prefill with transient per-layer KV materialization. Native DSA prefill applies the real indexer selection. Dense decode includes the complete history. Once sparse, the real query selects history at each step using Quest bounds or the native indexer Top-K. A foreground kernel loads missing KV before attention; existing hits require no transfer. The first decode uses this same path to initialize residency. Draft predictions only warm the next step's cache: a prediction miss adds foreground I/O, rather than removing an entry from the real selection. Retained prefetched entries outside the real selection are masked from attention.

## Run the generic backend

Use Linux with an NVIDIA CUDA installation compatible with this repository's pinned PyTorch and kernel dependencies. Set `MODEL_PATH` and `DRAFT_MODEL_PATH` to local checkpoints or Hugging Face repository IDs. Authenticated downloads use your normal Hugging Face credentials. The example uses one GPU; increase `--tp` only when the model and draft support that tensor-parallel configuration.

{/* TODO: Validate these launch templates with real checkpoints on CUDA; this extraction environment provides CPU only. */}

```bash
python -m sglang.launch_server \
  --model-path "$MODEL_PATH" \
  --speculative-draft-model-path "$DRAFT_MODEL_PATH" \
  --attention-backend oasiskv \
  --dtype bfloat16 --kv-cache-dtype bfloat16 \
  --disable-radix-cache \
  --tp 1 --max-running-requests 4 \
  --context-length 16384 --max-total-tokens 32768 \
  --hisparse-config '{"top_k":2048,"block_size":16,"max_new_blocks":16,"prefill_chunk_size":128}'
```

Use this template for full causal MHA/GQA models such as Llama/Qwen and for ordinary absorbed MLA. For native DSA, replace the JSON with:

```json
{"top_k":2048,"block_size":1,"max_new_blocks":256,"prefill_chunk_size":128}
```

Native DSA requires `block_size=1`. If you omit `top_k`, it uses the model's `index_topk`. The native indexer still determines candidates; setting a smaller budget truncates those candidates. Native DSA shared-index layers consume the carried logical Top-K through the same backend.

Do not pass `--enable-hisparse` for the generic path. OasisKV defaults to EAGLE-3; you can select `--speculative-algorithm EAGLE3` or `--speculative-algorithm DSPARK` explicitly. Both use one candidate and two target rows. In OasisKV mode this flag selects the proposal worker only: draft tokens are always discarded. The draft runner uses its own attention backend and KV pool.

| JSON field | Default | Meaning |
| --- | --- | --- |
| `top_k` | 2048, or native DSA `index_topk` | Historical token budget per KV head. The active block is retained separately. |
| `block_size` | 16; native DSA 1 | Tokens per logical Quest block. Must divide `top_k`. |
| `max_new_blocks` | `null` | Maximum background admissions per KV head and step. `null` admits all predicted misses; zero disables predicted miss transfers. Real-query miss refill is always uncapped. |
| `prefill_chunk_size` | 256 | Query rows per long-request prefill chunk when host history is materialized. Smaller values reduce that transient workspace. |
| `copy_kernel` | `tiled` | Generic full-graph UVA copy implementation. `legacy` restores the original fixed four workers per request/head for A/B testing. Does not change eager or DeepSeek-V4 copies. |
| `refill_ctas_per_sm` | 8 | Positive integer multiplier of GPU SM count for the full-graph tiled real-query copy CTA budget. |
| `prefetch_ctas_per_sm` | 1 | Separate CTA budget multiplier for tiled background copies, to limit competition with foreground computation. |

The tiled copy grid stays within its total CTA budget even when the captured
batch has more request/head groups than that budget. CTAs iterate over remaining
groups and payload tiles; this does not drop selected misses. A CTA budget does
not reserve SMs or isolate memory bandwidth. Tune background copies using both
foreground latency and end-to-end throughput. Restart the server to recapture
graphs after changing these options; `legacy` ignores both budget options.

Generic MHA/GQA and ordinary MLA requests remain dense while their committed length is at most `top_k`. They allocate physical pages on demand from a layer-wide pool, without host history. Crossing the threshold backs up history to pinned memory and reuses existing GPU pages as sparse slots; it does not move the page table or allocate a second working set. Dense and sparse rows share the decode kernel and can coexist in the same graph bucket. Pages return to the pool after outstanding readers and writers finish. Native DSA retains its model-defined sparse selection from the start.

The target's persistent GPU KV payload is bounded by `(top_k + block_size)` tokens per local KV head and layer. Quest summaries still grow with context length; native DSA retains its growing indexer cache instead. Host history grows with live sparse requests. Pool slabs grow without moving existing pages; free pages are reusable across requests. Memory profiling still reserves the worst-case working set per allowed request, so lazy page allocation alone does not increase the scheduler admission limit. The draft's full KV history remains on GPU. Memory profiling reserves the target working sets, summaries/indexer keys, draft KV, and prefill workspace. Set `--max-total-tokens`, context length, and concurrency to fit both host RAM and GPU memory.

The generic implementation keeps target and draft decode CUDA graphs enabled by default. A fixed GPU request table supplies current host/device pointers, lengths, capacities, and LRU steps. Request allocation, host growth, and ownership updates run outside replay; kernels capture root KV backup, summary updates, prediction, real-query refill, and attention. Selection and transfer use independently captured per-layer graphs, connected to the foreground by CUDA external events. The host queues these graphs immediately after submitting the foreground graph. Selection waits for prediction and real refill; transfer additionally waits for attention to finish reading the page slots. The foreground graph has no model-tail join: the next step waits only when it reaches the corresponding layer. Private per-layer metadata snapshots preserve request ownership across reorder, padding, and batch-bucket changes. Allocation, threshold transitions, and reclamation may still require fences for the affected storage. Use `--disable-cuda-graph` for an eager comparison. Variable-length dense prefill remains eager.

The backend supports full causal self-attention with unquantized FP16/BF16 KV (FP32 for tensor reference tests). Pipeline/context parallelism, DSA layer sharding, the separate `--enable-unified-memory` allocator option, radix prefix reuse, hybrid sliding-window/recurrent models, attention sinks, custom score modifiers, and PD disaggregation are outside this path. DeepSeek-V4 uses its specialization below.

## Run the DeepSeek-V4 specialization

Keep the model and hardware settings required by your existing DeepSeek-V4 deployment. Add a compatible EAGLE-3 draft and the OasisKV prefetcher:

```bash
python -m sglang.launch_server \
  --model-path "$DSV4_MODEL_PATH" \
  --speculative-draft-model-path "$DSV4_DRAFT_MODEL_PATH" \
  --trust-remote-code --tp 4 \
  --disable-radix-cache --max-running-requests 4 \
  --enable-hisparse \
  --hisparse-config '{"device_buffer_size":4096,"host_to_device_ratio":4,"prefetcher":"oasiskv","prefetcher_config":{"size":512}}'
```

Here `prefetcher_config.size` counts logical C4 entries, so 512 entries cover 2048 original tokens. It is independent of the generic backend's block budget. The restored path includes per-layer prefetch task rings, generation/position validation, C4 transactional scratch, root-only commit, logprob row selection, and target/draft CUDA graph support. Indexer prediction and attention use the foreground stream, with the real Top-K miss refill between them. The draft row shares the real row's resolved history and does not trigger another immediate refill.

The V4 foreground graph records a per-layer prediction event after real-query refill. Independently captured background graphs wait on these events to run selection. Selection snapshots token/LRU metadata and records misses without changing live KV. After that layer's attention, the transfer stream waits for selection, copies host KV directly into the resident slots, and publishes the planned metadata. This can overlap the layer's FFN, later layers, and early layers of the next step. The graph reuses fixed per-layer ring scratch; it allocates no extra KV staging buffer. Padding rows cannot publish metadata even when their request IDs repeat a live request.

Captured selection admits only C4 entries that were committed before the paired forward. A C4 completed by the current real token remains in transactional scratch for attention, then moves to its fixed slot after the graph finishes. Draft-only C4 entries are discarded. Root-only C4 promotion waits for selection metadata readers, without waiting for historical transfers. Short-context transfer skips metadata publication, preserving any promoted fixed-slot entry; long-context transfer never writes the reserved newest slot. C4 host-page allocation, promotion, and scratch rollback remain outside the captured target forward. The next forward consumes the previous transfer at the corresponding layer rather than at the model boundary.

With `--disable-cuda-graph`, steps without an active C4 transaction keep the same per-layer selection/attention/transfer ordering. Eager C4-boundary steps still plan and transfer after commit. Switching between eager and graph execution waits for outstanding writers before reusing ring scratch. Request reclamation waits for both graph transfers and any later C4 commit before freeing host pages.

Before running a full V4 model, run the checkpoint-free CUDA regression from the repository root:

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/cuda_graph/test_oasiskv_async_graph.py \
  test/registered/cuda_graph/test_oasiskv_v4_cuda_graph.py
```

It covers two layers and multiple graph buckets, real-query misses, byte-exact V4 KV reads, padding, request reordering/reuse, short and long C4 boundaries, root-only commit, and the native 512-entry selection width. This test is skipped without a CUDA GPU; it does not validate the complete V4 indexer or attention model.

See [HiSparse](/docs/advanced_features/hisparse_guide) for the underlying C4 pool configuration.

## Use DSPARK proposals

For NVIDIA CUDA on Linux, use a DSPARK checkpoint compatible with your target's vocabulary, embedding dimensions, auxiliary feature layers, and feature normalization. Set `MODEL_PATH` and `DSPARK_MODEL_PATH` to local checkpoint directories or Hugging Face model IDs. For a full causal MHA/GQA target such as Qwen, a single-GPU example is:

```bash
python -m sglang.launch_server \
  --model-path "$MODEL_PATH" \
  --speculative-algorithm DSPARK \
  --speculative-draft-model-path "$DSPARK_MODEL_PATH" \
  --attention-backend oasiskv \
  --disable-radix-cache --tp 1 --max-running-requests 8 \
  --cuda-graph-config '{"decode":{"backend":"full","max_bs":8}}' \
  --hisparse-config '{"top_k":2048,"block_size":16}'
```

For DeepSeek-V4, add `--speculative-algorithm DSPARK` to the HiSparse specialization command above and point its draft path to the matching DSPARK checkpoint. If the target checkpoint bundles DSPARK weights and configuration, you may omit the draft path; DSPARK then loads its weights from the target checkpoint.

OasisKV fixes the runtime DSPARK block size to one (`gamma=1`) and the target window to two rows. You do not need to edit the checkpoint config or remove trained layers. Explicit block sizes greater than one are rejected. DSPARK proposes the next token; the target's probe row produces the per-layer Quest or native indexer Top-K used for prefetch. Real queries still determine attention's working set and refill every miss. Even an exactly matching proposal is never accepted.

Only real target rows update DSPARK's context KV. V4 also promotes only real C4 entries and clears uncommitted C128 draft state. The candidate's temporary target KV does not extend the committed history. Eager and full-graph paths use the same ownership rules.

Target decode graphs retain the fixed two-row layout; DSPARK draft decode graphs use one row per request and can retain their existing folded proposal sampler. OasisKV bypasses DSPARK confidence scheduling, compact/ragged verification, and speculative acceptance, even if `SGLANG_RAGGED_VERIFY_MODE=compact` is set. Target feature injection and V4 C4 commit remain outside the target graph, as in the existing workers.

The DSPARK adapter has checkpoint-free CPU tests for metadata preparation, request reordering/reuse, root-only output and feature commit, and C4 rollback. CUDA capture/replay regressions include DSPARK metadata but skip without a GPU. Validate full-model generation and prefetch hit rate with your actual checkpoint before comparing TPOT or TPS; single-candidate lookahead does not exercise DSPARK's usual multi-token acceptance benefit.

## Branch provenance

`oasiskv` branches from `c5653f90d`, immediately before the first OasisKV change. This is its common ancestor with the reviewed `heykon_main` tip, `aaff55ab608ebecb09887ac4d293edc7700acb69`. The base retains the HiSparse/EAGLE infrastructure that the implementation depends on.

The extraction carries the following original commits, with cherry-pick provenance in Git:

```text

b81f49d9c d34ebec94 8d8e04527 870dedb75 d11431c49 984b65114
8a2660ba1 0737cb9d1 7a490c488 007e61025 6f8f19bde
```

The relevant logical-entry sizing fix from `21a4fd44d` is ported separately. Commit `3dc681372` had replaced lookahead-only execution with normal EAGLE acceptance and removed the C4 draft prediction producer. This extraction restores the producer, shared root/draft working set, and forced draft discard from before that deletion. Normal EAGLE acceptance remains available in ordinary speculative decoding, outside OasisKV mode.

Compare dense, synchronous sparse, uncapped lookahead, and capped lookahead runs with identical prompts, sampling, and memory budgets.
