---

This branch implements the lookahead execution contract from [OasisKV v1](https://arxiv.org/pdf/2608.08097v1): run a real token and one draft token through the target, use the draft query to prepare the next working set, and commit only the real token. You need a compatible EAGLE-3 draft checkpoint; an arbitrary smaller language model is not a substitute.

The generic backend is an experimental eager implementation. CPU tensor and integration tests cover its attention, ownership, configuration, and memory accounting. CUDA copies, full model generation, quality, and performance still require validation on NVIDIA GPUs. This branch does not implement the paper's remote partial fetch service or claim its reported speedups.

## Choose a path

| Target attention | Selection for next step | Target KV storage | Entry point |
| --- | --- | --- | --- |
| MHA / GQA | Quest min/max bounds per KV head, maximum across that head's query group | Full history in pinned CPU memory; bounded GPU block slots | `--attention-backend oasiskv` |
| Ordinary MLA | Quest over the absorbed latent-plus-RoPE keys and queries | One latent KV head with separate key and value dimensions | `--attention-backend oasiskv` |
| Native DSA, including DeepSeek-V3.2 / GLM DSA | The model's real draft-row indexer Top-K, before physical-page translation | CPU latent KV; bounded GPU KV slots; native indexer key cache stays on GPU | `--attention-backend oasiskv` |
| DeepSeek-V4 | C4 draft-row indexer Top-K | Existing HiSparse C4 host/device pools and transactional scratch | `--enable-hisparse`, `prefetcher="oasiskv"` |

For the generic path, both rows attend to the same resident history. The draft row can also see its own provisional KV; the real row cannot. Only real KV is appended to host history. The prediction, LRU delta selection, and UVA copy stages use separate CUDA streams. Each layer waits for its own previous transfer before reuse. Releasing or reusing a request waits for outstanding copies before freeing pinned memory.

Prefill uses causal attention with chunked queries and transient per-layer KV materialization. Native DSA prefill applies the real indexer selection. The first decode seeds the resident set from the real query. Subsequent steps consume the preceding draft's predicted set, without synchronously replacing it with the current real query's Top-K.

## Run the generic backend

Use Linux with an NVIDIA CUDA installation compatible with this repository's pinned PyTorch and kernel dependencies. Set `MODEL_PATH` and `DRAFT_MODEL_PATH` to local checkpoints or Hugging Face repository IDs. Authenticated downloads use your normal Hugging Face credentials. The example uses one GPU; increase `--tp` only when the model and draft support that tensor-parallel configuration.

{/* TODO: Validate these launch templates with real checkpoints on CUDA; this extraction environment provides CPU only. */}

```bash
python -m sglang.launch_server \
  --model-path "$MODEL_PATH" \
  --speculative-draft-model-path "$DRAFT_MODEL_PATH" \
  --attention-backend oasiskv \
  --dtype bfloat16 --kv-cache-dtype bfloat16 \
  --disable-radix-cache \
  --tp 1 --max-running-requests 4 \
  --context-length 16384 --max-total-tokens 32768 \
  --hisparse-config '{"top_k":2048,"block_size":16,"max_new_blocks":16,"prefill_chunk_size":128}'
```

Use this template for full causal MHA/GQA models such as Llama/Qwen and for ordinary absorbed MLA. For native DSA, replace the JSON with:

```json
{"top_k":2048,"block_size":1,"max_new_blocks":256,"prefill_chunk_size":128}
```

Native DSA requires `block_size=1`. If you omit `top_k`, it uses the model's `index_topk`. The native indexer still determines candidates; setting a smaller budget truncates those candidates. Native DSA shared-index layers consume the carried logical Top-K through the same backend.

Do not pass `--enable-hisparse` or an explicit `--speculative-algorithm` for the generic path. OasisKV configures EAGLE-3 internally with one draft step, top-k one, and two target rows. Draft tokens are always discarded. The draft runner uses its own ordinary Triton or native DSA backend and its own KV pool.

| JSON field | Default | Meaning |
| --- | --- | --- |
| `top_k` | 2048, or native DSA `index_topk` | Historical token budget per KV head. The active block is retained separately. |
| `block_size` | 16; native DSA 1 | Tokens per logical Quest block. Must divide `top_k`. |
| `max_new_blocks` | `null` | Maximum newly admitted historical blocks per head and step. `null` admits all misses; zero freezes historical slots after initial seeding. |
| `prefill_chunk_size` | 256 | Query rows per dense prefill chunk. Smaller values reduce transient prefill workspace. |

The target's persistent GPU KV payload is bounded by `(top_k + block_size)` tokens per local KV head and layer. Quest summaries still grow with context length; native DSA retains its growing indexer cache instead. Host history grows with live requests. The draft's full KV history remains on GPU. Memory profiling reserves the target working sets, summaries/indexer keys, draft KV, and prefill workspace. Set `--max-total-tokens`, context length, and concurrency to fit both host RAM and GPU memory.

The generic implementation disables target and draft CUDA graphs. It supports full causal self-attention with unquantized FP16/BF16 KV (FP32 for tensor reference tests). Pipeline/context parallelism, DSA layer sharding, unified KV pools, radix prefix reuse, hybrid sliding-window/recurrent models, attention sinks, custom score modifiers, and PD disaggregation are outside this path. DeepSeek-V4 uses its specialization below.

## Run the DeepSeek-V4 specialization

Keep the model and hardware settings required by your existing DeepSeek-V4 deployment. Add a compatible EAGLE-3 draft and the OasisKV prefetcher:

```bash
python -m sglang.launch_server \
  --model-path "$DSV4_MODEL_PATH" \
  --speculative-draft-model-path "$DSV4_DRAFT_MODEL_PATH" \
  --trust-remote-code --tp 4 \
  --disable-radix-cache --max-running-requests 4 \
  --enable-hisparse \
  --hisparse-config '{"device_buffer_size":4096,"host_to_device_ratio":4,"prefetcher":"oasiskv","prefetcher_config":{"size":512}}'
```

Here `prefetcher_config.size` counts logical C4 entries, so 512 entries cover 2048 original tokens. It is independent of the generic backend's block budget. The restored path includes per-layer prefetch task rings, generation/position validation, C4 transactional scratch, root-only commit, logprob row selection, and target/draft CUDA graph support. With `--disable-cuda-graph`, non-C4-boundary steps can submit each layer immediately; C4-boundary steps wait for commit. Graph replay publishes pending tasks after replay, so it does not provide the generic eager path's same-forward layer overlap.

See [HiSparse](/docs/advanced_features/hisparse_guide) for the underlying C4 pool configuration.

## Branch provenance

`oasiskv` branches from `c5653f90d`, immediately before the first OasisKV change. This is its common ancestor with the reviewed `heykon_main` tip, `aaff55ab608ebecb09887ac4d293edc7700acb69`. The base retains the HiSparse/EAGLE infrastructure that the implementation depends on.

The extraction carries the following original commits, with cherry-pick provenance in Git:

The relevant logical-entry sizing fix from `21a4fd44d` is ported separately. Commit `3dc681372` had replaced lookahead-only execution with normal EAGLE acceptance and removed the C4 draft prediction producer. This extraction restores the producer, shared root/draft working set, and forced draft discard from before that deletion. Normal EAGLE acceptance remains available in ordinary speculative decoding, outside OasisKV mode.

## Validate the port

Run from the repository root in an environment with this checkout's dependencies:

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/unit/mem_cache/test_oasiskv_cache.py \
  test/registered/unit/mem_cache/test_oasiskv_backend.py \
  test/registered/unit/mem_cache/test_oasiskv_pool.py \
  test/registered/unit/spec/test_oasiskv_lookahead.py \
  test/registered/unit/test_hisparse_prefetcher.py
```

The CUDA test skips when CUDA is unavailable. On CUDA, it exercises the actual UVA copy kernel and checks selected payloads after the stream pipeline. Before comparing throughput, validate multi-request generation, request cancellation and slot reuse, prompt/decode boundary crossings, logprobs, and long-context quality for each target/draft pair. Compare dense, synchronous sparse, uncapped lookahead, and capped lookahead runs with identical prompts, sampling, and memory budgets.
